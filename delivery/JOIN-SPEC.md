# JOIN-SPEC — מפרט צד-השרת לשער ההרשמה (למסירה לאיתי)

*נכתב 2.8.2026 ע"פ פריט 🚪 ב-NEXT (הוראת OC). זהו מפרט, לא קוד —
שלושה מארבעת השלבים חיים מחוץ לריפו האתר, ושניים מהם בריפו
הפלטפורמה של איתי. האתר בנה את חלקו (טופס `/join`, מכונת-מצבים,
שכבת-סליקה מופשטת, אנליטיקס) והשאר מוגדר כאן.*

## הזרימה המלאה (יעד)

```
מבקר → /join (אתר) → פרטים + הסכמה → [בעתיד: סליקה אצל ספק]
     → נשמר ליד → השרת מנפיק טוקן חד-פעמי → מייל עם קישור
     → המבקר פותח את הקישור → הפלטפורמה מממשת את הטוקן → כניסה
```

מתג אחד באתר (`FREE_MODE` ב-`join/join.js`) קובע אם שלב-הסליקה
קיים בזרימה. כרגע `true` (המסלול חינם).

## מה צריך להיבנות בצד הפלטפורמה (איתי)

### 1. קליטת ליד
- קלט מהאתר: `{ name, email, phone, consent: true, ts }`.
- **יעד הליד טרם הוכרע** (החלטת OC פתוחה): ‏(א) Firestore של
  הפלטפורמה (יש רמז ל-`leads` ב-firestore.rules.PENDING-leads-admin)
  · ‏(ב) שירות טפסים חיצוני · ‏(ג) מייל ל-OC בלבד בשלב ראשון.
  האתר עובד מול `submitLead()` מופשט — כל יעד שייבחר מתחבר בנקודה
  אחת.

### 2. הנפקת טוקן חד-פעמי
- טוקן אקראי קריפטוגרפית (לא ניחוש-בר: ‏128bit+, למשל
  `crypto.randomUUID()` או 32 תווי hex מ-CSPRNG).
- נשמר עם: ‏email · ‏ts הנפקה · **תפוגה** (מומלץ 72 שעות) ·
  דגל `used`.
- טוקן = הרשאת-כניסה, לכן צד-שרת בלבד (Cloud Function / שרת).
  **אסור להנפיק בצד-לקוח** — לקוח שמנפיק לעצמו הרשאה אינו שער.

### 3. שליחת המייל
- אל: כתובת המייל מהטופס. תוכן: קישור
  `https://<platform>/?join=<token>` (או נתיב ייעודי).
- שירות שליחה לבחירת איתי (Firebase Extensions / SendGrid / אחר).
- לציין בעדינות שהקישור אישי וחד-פעמי.

### 4. מימוש הטוקן בכניסה
- הפלטפורמה מקבלת `?join=<token>`: בודקת קיום · לא-פג · לא-`used`.
- תקין → מסמנת `used`, יוצרת/מקשרת משתמש, מכניסה.
- פג/נוצל/לא-קיים → מסך שגיאה עדין + קישור לבקשת קישור חדש
  (חוזר ל-`/join` באתר).

## ⚠️ אזהרת האבטחה (חובה לקרוא, מנוסח ב-NEXT ומתועד גם ב-HANDOFF)

‏`AUTH-PLAN.md` בפלטפורמה קובע שהיום **אין שום אימות** — זהות =
מספר טלפון מוקלד, וכללי Firestore פתוחים
(`allow read, write: if true`). כלומר גם אחרי שנבנה שער תשלום
מושלם באתר, **מי שיודע את כתובת הפלטפורמה ייכנס בלעדיו.** שער
שאפשר לעקוף אינו שער. זו הכרעת OC+איתי, לא שלנו — מתועד כאן
ובבירור: כל עוד זה המצב, אסור לטעון שהמסלול "נסגר" מאחורי תשלום.
סגירה אמיתית = מימוש-טוקן חובה בצד הפלטפורמה + כללי Firestore
שדורשים זהות מאומתת.

## איפה זה נשבר היום (סיכום לאיתי)

| נקודה | מצב |
|---|---|
| טופס /join באתר | ✅ קיים (מכונת-מצבים + ולידציה נגישה) |
| שמירת ליד | ⏳ ממתין להכרעת-יעד של OC; באתר דמה מתועד |
| הנפקת טוקן + מייל | ❌ לא קיים — סעיפים 2-3 כאן |
| מימוש טוקן בפלטפורמה | ❌ לא קיים — סעיף 4 כאן |
| אכיפה בצד הפלטפורמה | ❌ אין Auth (ראה אזהרה) |

## סליקה (כשתגיע)

האתר כבר מדבר עם ממשק מופשט: `createCheckout(order)` מחזיר
`{ redirectUrl }` של דף-סליקה **מאוחסן אצל הספק**, ו-
`verifyReturn(params)` מאמת חזרה. בחירת ספק (Grow / משולם /
Stripe / PayPal) = מימוש אחד מוחלף, הזרימה לא משתנה. **האתר
לעולם לא אוסף פרטי אשראי בעצמו.**

## אנליטיקס (כבר חי באתר)

‏`shift:join_start` (מיקוד ראשון בטופס) · ‏`shift:join_submit`
(שליחה עברה ולידציה) · ‏`shift:join_holding` (מצב-החזקה, כל עוד
אין יעד-ליד) · ‏`shift:join_success` (יופעל רק כשהזרימה אמיתית).
